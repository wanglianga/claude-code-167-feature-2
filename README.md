# 畅观博物馆 · 无障碍参观预约与接待系统

面向博物馆无障碍服务的单页应用（前端项目，无需后端服务）。把**观众预约、无障碍路线、轮椅/车位等设备、讲解员/志愿者排班、入馆核验、展厅接应、突发处置、参观后回访**放在**同一条参观服务记录**中，兼顾文化服务体验与现场安全。

技术栈：**React 18 + TypeScript + Vite + Zustand（localStorage 持久化）+ React Router**，无 UI 组件库依赖。

## 功能与需求对应

### 观众预约（手机端 `/book`）
- 填写参观日期、预计到馆时间、人数。
- 需求开关：**是否使用（自带）轮椅、是否借用馆方轮椅、是否需要手语讲解、是否需要慢速讲解、是否有老人/儿童同行、是否需要近距离无障碍车位、能否长时间站立**。
- 填写时右侧**实时给出"路线可行性预估"**：可安排展厅数、总距离、总时长、时段、轮椅库存、车位、陪同排班与各项提示。

### 可行路线生成（`src/lib/planner.ts`）
路线同时考虑 5 类约束：**展厅覆盖 × 观众体力 × 设备可用 × 展厅拥挤 × 工作人员接应能力**。
- 馆区图模型：B1 特展层、F1 大厅服务台、F2 古代馆、F3 近代/自然馆；节点含展厅、电梯、坡道、休息点、无障碍卫生间、无障碍车位、服务台。
- Dijkstra 寻路（电梯故障时自动剔除故障电梯、全程绕行备用电梯；双梯全停时跨层展厅安全跳过且不崩溃）。
- 每段路线提示：**距离、最大坡度、步行/乘梯耗时、预计到达时间、休息点、无障碍卫生间位置、需要协助的动作**。
- 按体力调整步速与步行预算（轮椅 / 慢速 / 老人 / 不能久站），低体力路线自动插入休息点与卫生间途经点。
- 拥挤度按开馆双峰（10:30、14:30）+ 展厅热度确定性测算，并支持工作人员人工覆盖；**过度拥挤展厅自动避让**。
- 临时闭馆展区自动移出；闭馆时间/返回缓冲不足的展厅不排入。
- 轮椅库存、无障碍车位、讲解员/志愿者排班（技能：手语/慢速/轮椅协助、班次、请假、时段冲突、楼层接应位容量）统一核算并给出降级方案。
- **多预约同时借轮椅的库存协调**：按到馆时间轴模拟设备发放（含已借出者的参观结束+周转消毒的**归还预计**），给出到馆可发台数、排队位次、等待分钟、最早可领时间；按日期测算**东/西/南馆区可调余量与搬运耗时**；"优先借用"在设备释放时优先发放；跨馆调入走独立通道不占本馆池。

### 入馆当天（馆内平板工作台 `/ops`）
- **服务台**：核验预约、办理入馆、借出/归还轮椅（记录资产编号与时间）、确认车位、安排/人工改派讲解员或志愿者。
- **轮椅库存不足协调台**：多个预约同时需要轮椅时，一屏展示**本馆库存、每组观众到馆时间、同段借用组数、排队位次、最早可领时间与前序设备归还预计（资产编号/借用人/预计归还时刻）、其他馆区可调设备（余量、距离、搬运耗时、搬运人员）**。
  - 本馆无法满足时可逐组处置：**📞 联系观众自带设备、🕐 调整参观时段、⭐ 安排优先借用**，处置均须**记录原因**并写入该条服务记录；处置后库存、排队、路线、排班自动重算。
  - **调用其他馆区轮椅**：选择东/西/南馆区发起调运，跟踪**搬运人员及电话、预计到达时间、当前观众等待位置**（可随时更新），状态流转"已请求 → 已取货出发 → 已送达"，送达后一键发放调入轮椅（归还时标注来源馆区）。
  - 等待期间服务台可提供**🪑 座椅、💧 饮水、🎧 临时讲解**，一键登记即进入预约记录；观众端 `/visit/:id` 同步展示排队位次、归还预计、调运进度、等待位置与已提供的照料服务。
- **展厅工作人员**：在"今日接应任务看板"按时间看到每组观众的**预计到达时间、人数、是否轮椅、拥挤度与需要协助的节点**。
- **现场调度**：一键设置电梯临时故障、展区临时闭馆、展厅拥挤度、讲解员临时请假、轮椅报修/归库；**变更后所有相关预约的路线、排班、设备（含轮椅排队位次与归还预计）与提示自动重算**（路线版本递增并写入服务记录）。
- 支持处置：观众迟到、观众身体不适（自动缩减路线、加密休息）、陪同人临时增加、突发协助（坡道推行、电梯接应、医护联系、卫生间引导等自定义记录）。

### 同一条服务与服务延续（观众端 `/visit/:id`）
- 馆区平面图高亮实际路线（电梯、坡道、休息点、卫生间、闭馆/故障、拥挤点）。
- 完整分段路线时间线（距离、坡度、休息点、卫生间、预计到达）。
- 观众可手机自助报备迟到、身体不适、给服务台留言。
- **服务记录时间线**：预约前（book/排班/车位）、入馆中（核验、轮椅借还、路线调整、协助、突发）、参观后（归档、反馈偏好）全程留痕；反馈偏好用于"下次接待延续"。
- 数据通过 Zustand persist 保存在浏览器 localStorage，刷新不丢失。

## 目录结构

```
src/
  types.ts              领域模型（预约/路线/设备/人员/服务事件/轮椅协调与跨馆调运）
  data/museum.ts        馆区节点图、通道/电梯/坡道、展厅、库存、跨馆轮椅池、排班
  lib/planner.ts        路线规划引擎：寻路、拥挤度、库存/排队/归还预计/跨馆可调、车位/排班约束、突发重算
  store.ts              Zustand store：全链路动作（含轮椅协调/调运/等候服务）+ 持久化 + 演示数据
  components/           馆区平面图、路线时间线、轮椅库存协调台、通用 UI
  pages/                首页(手机端我的预约) / 预约 / 参观详情 / 馆内工作台
scripts/                规划场景断言、store 冒烟、SSR 渲染冒烟
Dockerfile / nginx.conf / docker-compose.yml   一键启动
```

## 本地启动

### 方式一：Docker 一键启动（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

多阶段构建：Node 22 构建静态产物 → nginx 1.27 托管（含 SPA history 回退），容器带健康检查。

### 方式二：本地开发（Node 22）

```bash
npm install
npm run dev          # http://localhost:5173 ，热更新
npm run build        # 类型检查 + 生产构建到 dist/
npm run preview      # 预览生产构建
```

> 若本机 npm 缓存目录权限异常（EACCES），可指定本地缓存：
> `npm install --cache ./.npm-cache`

- 观众手机端：首页 `/`、预约 `/book`、参观详情 `/visit/:id`（可用浏览器 DevTools 切手机视口）。
- 馆内平板端：`/ops`（建议横屏/平板视口）。

## 已执行的验证结论

- ✅ `npm run build`：TypeScript 严格模式 0 错误，Vite 生产构建成功。
- ✅ `npm test`：56 + 34 + 36 = **126 项断言全部通过**。
- ✅ `npm run preview` 启动后 `curl http://localhost:5173/` 返回 `200` 与应用 HTML，`/ops` 等前端路由 SPA 回退同样返回 `200`。
- ⚠️ 当前开发环境**未提供 Docker 守护进程**，因此 Dockerfile/Compose **未能在本环境实际构建镜像**；构建流程（多阶段 + nginx SPA 回退）已按标准方式编写，请在装有 Docker 的环境执行 `docker compose up --build` 做最终确认。
- 说明：应用为纯前端演示，排班、拥挤度、库存、馆际调拨为内置确定性模型与本地数据；真实接入时可将 `src/lib/planner.ts` 的输入与 `src/store.ts` 的动作替换为后端 API，页面与状态结构无需改动。
